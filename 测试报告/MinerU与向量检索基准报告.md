# MinerU 与向量检索基准报告

测试日期：2026-08-06（北京时间）

## 1. 测试结论

- MinerU 已完成从安装、模型下载、中文路径兼容到应用调用的闭环，可以处理纯图片扫描 PDF 和复杂表格。
- 当前 CPU 版 MinerU 单页端到端耗时约 52 秒，准确率较高，但对 16GB 内存机器的虚拟内存压力明显，应继续作为按需增强能力，不宜对所有 PDF 默认开启。
- Qwen3-Embedding-0.6B 已作为独立服务部署在 `127.0.0.1:11435`，不影响 `11434` 的 Qwen3-4B 对话服务。
- 104 个知识文件、12 个真实业务问句的基准中，混合检索相对关键词检索提升了 Top-1、Top-3 和 MRR，达到当前接入条件。
- 本轮工程回归共 102 项自动化测试通过，静态编译和依赖完整性检查正常。

### 2.2 样本与准确率

从公开中文招标文件第 8 页生成 220 DPI、`1820 x 2573` 像素的纯图片 PDF。重新打开后原生文本层为 0 字符，页面包含长表格，适合作为扫描件基准。

| 指标 | 原生解析 | MinerU 应用闭环 |
| --- | ---: | ---: |
| 解析耗时 | 0.0016 秒 | 52.34 秒 |
| 提取字符数 | 0 | 756 |
| 疑似扫描件 | 是 | 否 |
| 规范化字符相似度 | 0 | 99.36% |
| 关键字段召回 | 0/15 | 15/15 |

关键字段覆盖条款号、招标代理机构、建设地点、计划工期、质量要求、安全目标、资质条件、联合体、踏勘、预备会和分包等内容。

同日第二次完整应用闭环复跑耗时 57.36 秒，仍提取 756 个字符、规范化字符相似度 99.36%、关键字段 15/15，说明结果稳定；CPU 单页耗时可按约 52 至 58 秒估算。

### 2.3 本轮修复

- Windows 原生 `fasttext` 无法打开包含中文目录名的模型路径。安装脚本现创建 `%LOCALAPPDATA%\BidAssistantRuntime\mineru-venv` ASCII 目录联接，并使用 `python -m mineru.cli.client` 启动。
- MinerU 3.4.4 的表格正文位于 `table_body`。应用现将表格 HTML 转成按行、按列可检索文本，不再只得到标题。
- 应用自动传入中文 OCR 模式、ModelScope 模型源和项目内模型配置；失败时仍保留原生解析结果。

### 2.4 使用建议

- 普通带文本层 PDF：继续使用“自动”或“快速原生”。
- 少量扫描件：使用“自动”，仅疑似扫描件调用 MinerU。
- 批量扫描件成为常态后，再评估 CUDA 版 PyTorch 或独立 OCR 工作站；当前 CPU 配置不适合持续批处理。

## 3. 向量检索测试

### 3.1 服务配置

| 项目 | 实测结果 |
| --- | ---: |
| 模型 | Qwen3-Embedding-0.6B-Q8_0 |
| 模型文件 | 609.54 MiB |
| SHA-256 | `06507c7b42688469c4e7298b0a1e16deff06caf291cf0a5b278c308249c3e439` |
| 向量维度 | 1024 |
| 服务地址 | `http://127.0.0.1:11435/v1` |
| 服务启动 | 约 16.5 秒 |

模型来源为 ModelScope 官方 `Qwen/Qwen3-Embedding-0.6B-GGUF`。服务使用 llama.cpp 的 `--embeddings --pooling last` 参数，并与对话模型分端口运行。

### 3.2 语料与问句

- 原始模拟知识文档：14 份。
- 按标题和长度拆分后的独立知识文件：104 份。
- 类别：企业资料、产品资料、历史方案。
- 真实业务问句：12 个，覆盖资质、人员、施工验收、材料选型、类似业绩、医院不停诊、售后、财务和安全措施。

分片保留来源文档元数据，符合生产知识库常见做法；本次仍属于模拟资料回归，不能替代甲方真实资料验收。

### 3.3 命中率与耗时

| 模式 | Top-1 | Top-3 | MRR | 平均耗时 |
| --- | ---: | ---: | ---: | ---: |
| 关键词 | 66.7% | 83.3% | 0.750 | 0.125 秒 |
| 关键词 + 向量混合 | 75.0% | 100.0% | 0.875 | 0.477 秒 |

冷启动首轮混合检索建库及首问耗时 7.45 秒；模型服务热启动后的完整复跑为 3.91 秒。104 个文本块按 16 条批处理，共发出 7 次文档向量请求。向量缓存建立后，重复问句耗时 0.177 秒。

混合检索补回了关键词未进入 Top-3 的医院不停诊和雨水倒灌售后问题。质量体系问句仍排在第 2 位，说明后续可以继续调整 70% 向量、30% 关键词的权重，或增加小型重排模型。

