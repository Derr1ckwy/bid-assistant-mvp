# 投标初稿助手

面向单人开发和小范围试用的投标文件初稿生成系统。系统把招标文件解析、要求提取、人工确认、企业资料检索、章节草稿生成、自动复核和 Word 导出串成一条可追溯流程。

首次使用、客户培训或迁移到新电脑时，请先阅读 [用户操作与交付手册](./用户操作与交付手册.md)。手册详细说明每个功能的用途、边界、操作顺序、数据迁移、部署验收和常见故障。

当前目标不是“无人审核一键出标”，而是优先减少人工整理时间、暴露遗漏与废标风险，并确保没有企业事实依据时不编造内容。

## 已实现

- 本地创建、复制、归档、恢复和筛选投标项目
- 项目八阶段进度总览
- 项目完整 ZIP 备份、校验导入和重复项目兼容
- PDF、DOCX、TXT、Markdown 解析
- 规则模式提取项目、强制要求、评分项、资格、材料、时间和风险
- 可选 OpenAI 兼容 LLM 分析与章节生成，长文档自动分段合并
- 分析结果、原文页码、引用和章节计划的人工编辑确认
- 自动保存分析基线，对比人工确认结果统计命中、误报、漏项、修改和处理耗时
- 真实项目验收记录支持持久化，并可下载带明细的中文验收报告
- 企业资料、产品资料、历史方案三类知识资料上传、删除与轻量检索，支持 PDF、DOCX、TXT、Markdown、CSV、JSON
- 知识文件达到阈值且配置 OpenAI 兼容 Embedding 后自动切换关键词+向量混合检索，未配置时保持轻量关键词模式
- 规则或 LLM 章节草稿生成，无事实依据时保留“待补充/待确认”
- 草稿保存自动建立版本快照，可预览章节并恢复历史版本
- 自动检查遗漏、未确认条款、废标风险、缺失章节、占位符和证据缺失
- 检查工期、质保期、金额、日期、人员数量和资质有效期的跨章节冲突
- Word 导出前显示项目、章节、高风险、占位符和证据追溯检查清单
- Word 使用 V001、V002 递增版本，保留生成时间、风险摘要、版本说明和 SHA-256
- Word 历史版本下载前重新校验文件哈希、DOCX 结构、章节数量和系统标准版式
- Word 损坏或被替换时停止下载和提交打包，并允许导出中文质检报告
- 从招标分析同步最终提交材料清单，支持人工增删、分类、状态、页码、附件关联和备注
- 资格、商务、技术、报价、签章装订及其他附件分类管理，同名文件不会静默覆盖
- 最终提交材料清单可导出为 UTF-8 CSV，必交项完成情况纳入项目总进度
- 提交包生成前检查 Word 版本、清单保存状态、必交项、附件断链和复核风险
- 使用 `P001`、`P002` 递增生成版本化 ZIP，保留最近 20 版及 SHA-256
- 提交包汇总 Word、分类附件、材料清单、提交说明和逐文件校验清单
- 提交包下载前重新校验外层 SHA-256、ZIP 结构和包内逐文件哈希，损坏时停止下载
- 支持下载中文完整性校验报告，记录结论、错误项、提示项和文件明细
- 专业排版 Word 初稿：A4、封面、目录、首页不同、页眉页脚、页码、分析附录和复核报告
- 项目级真实 DOCX 模板适配，支持项目信息占位符和 `{{BID_CONTENT}}` 正文插入点
- PNG/JPG/JPEG 资质图片管理，Word 导出时自动生成两列等比缩放的资质证明材料
- 招标文件支持自动、快速原生和 MinerU 增强三种解析方式，增强失败自动保留原生结果
- GitHub Actions 自动编译和测试

## 快速启动

在 PowerShell 中执行：

```powershell
Set-Location -LiteralPath 'D:\灵坤\投标系统'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\run.ps1
```

浏览器访问 `http://127.0.0.1:8501`。

不配置模型也可以使用规则模式。需要 LLM 时，可直接在左侧“模型配置”中填写 OpenAI 兼容接口、模型名称和 API Key，检测连接后保存到本机 `.env`。

## 模型配置

默认配置面向 16GB 内存和 8GB 显存的当前单机环境：

```text
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL=qwen3:4b
LLM_CHUNK_CHARS=12000
LLM_MAX_CHUNKS=12
```

当前电脑已采用 Windows 原生 `llama.cpp` Vulkan 后端，不依赖 Ollama、Docker 或 WSL。首次重建环境时执行：

```powershell
.\setup_local_llm.ps1
.\start_local_llm.ps1
```

安装脚本通过国内 GitHub 代理下载 `llama.cpp` Windows Vulkan 运行时，并从 ModelScope 下载官方 `Qwen3-4B-Q4_K_M.gguf`，下载支持断点续传且会校验官方 SHA-256。模型和运行时分别位于 `models/`、`runtime/`，均被 Git 忽略。

`run.ps1` 会优先自动启动本地 `llama-server`，继续使用 `http://localhost:11434/v1`、模型别名 `qwen3:4b` 和本地 API Key `ollama`；服务只监听本机地址并限制浏览器来源。本地文件不存在时才尝试已有 Ollama。可用 `.\stop_local_llm.ps1` 停止由项目管理的模型进程。也可以改用任意 OpenAI 兼容云端接口；API Key 仅保存在被 Git 忽略的 `.env` 中，不进入项目备份。

模型健康检查会区分服务未启动、连接超时、鉴权失败、模型未下载和接口响应异常。选择 LLM 分析或生成时，若预检失败会立即切换到规则模式，不再等待完整请求超时。

## 项目备份

在左侧“项目管理”中可下载当前项目的完整 ZIP 备份，也可以在另一台安装了本系统的电脑上导入。备份包含源文件、分析结果、知识资料、草稿版本、复核状态、Word 输出、提交附件、材料清单和历史提交包，不包含模型密钥及其他项目。

导入时会检查备份格式、文件路径、文件数量、解压体积和 SHA-256；同一项目重复导入时会自动生成新的项目 ID，不覆盖原项目。

## Word 输出

- 正文使用宋体小四（12 磅）、固定值 26 磅行距，封面及各级标题统一使用宋体
- 封面采用项目名称、投标文件类型、招标人、投标人盖章位和日期的正式结构，封面不显示运行页眉和页脚
- 正文页眉显示项目名称和“投标文件”，页脚仅居中显示页码，不在正式文档中展示 AI 提示
- 列表使用 Word 原生编号并按逻辑分组从 1 重启；表格统一使用宋体小四（12 磅）、浅灰表头、黑字、细灰框线、内容感知列宽和重复表头
- 内部核对与复核报告默认不进入正式 Word，可在导出页按需勾选附带；长表格禁止单行跨页拆分
- 导出前自动清理 Markdown 代码围栏、YAML 元数据、重复章节标题和裸露的检索引用标记
- 存在未处理风险时必须显式确认“仅用于内部复核”，每次生成新文件而不覆盖旧版本
- Word 版本记录支持查看章节数、待处理数、高风险数和版本说明，并下载任意历史版本
- 选择历史版本后自动检查 SHA-256、DOCX 必要结构、A4 页面、正文样式、标题字距、页眉页脚、表格布局和占位内容
- 文件损坏、哈希变化、正文章节缺失或非 A4 时禁止下载；版式偏差和占位符作为需人工确认项
- 质检报告可独立下载，便于在交付前留存 Word 文件状态和人工处理依据
- 可在“知识资料”上传项目专属 DOCX 模板；支持 `{{PROJECT_NAME}}`、`{{PURCHASER}}`、`{{AGENCY}}`、`{{BUDGET}}`、`{{BID_DEADLINE}}`、`{{GENERATED_DATE}}` 和 `{{BID_CONTENT}}`
- 模板模式保留原模板分节、页眉页脚、字体和样式；找不到独立正文占位段落时将生成内容追加到文档末尾
- 资质图片自动按两列编排、等比缩放并使用文件名生成图注，导出历史记录所用模板和图片数量

当前示例成品位于 `D:\灵坤\投标系统\data\demo\示例投标文件初稿V3.docx`。没有真实模板时使用系统默认精排版；获得甲方模板后可直接按占位符适配。

## MinerU 与向量检索

MinerU 使用独立虚拟环境，避免其模型和依赖影响主应用：

```powershell
.\setup_mineru.ps1
```

自动识别模式先运行原生解析，仅在 PDF 文本过少时调用 MinerU；“MinerU 增强”会优先调用 MinerU。未安装、超时或解析失败时，系统保留原生解析并显示原因。MinerU 模型较大，首次运行需要额外下载时间和磁盘空间。

向量检索默认阈值为 40 个知识文件。配置 `EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL` 后，达到阈值自动启用混合排序；文件上传、删除或修改后相关缓存自动失效。小资料集及未配置向量模型时不产生额外服务依赖。

## 真实项目验收

每次重新分析招标文件时，系统会保存一份不可随人工编辑变化的分析基线。人工确认后，系统按条目 ID 对比基线与当前结果：已确认的原提取项计为命中，忽略或删除的原提取项计为误报，人工新增且未忽略的条目计为漏项。旧项目也可从当前结果建立后续迭代基线，但报告会明确标注来源，不能当作最初自动分析表现。

验收区可记录纯人工预计耗时、系统协助实际耗时、验收人和备注，并生成包含命中、误报、漏项、待确认明细的中文报告。存在未保存修改或待确认项时，验收记录会保持阶段性状态；解析结果与基线来源不一致时会停止保存和下载。覆盖率只在人工复核完成后计算，且仅作为真实项目迭代对比指标。

## 提交包

“7. 提交清单”页可选择任意历史 Word 版本并执行提交包预检。未保存的清单修改、待准备的必交项、附件断链或缺少 Word/清单会直接阻止打包；复核问题属于警告，必须显式确认本包仅用于内部预审。

每个 ZIP 包含：

- `投标文件/`：所选 Word 版本
- `提交附件/`：按资格、商务、技术、报价、签章装订和其他附件分类
- `最终提交材料清单.csv`：带 UTF-8 BOM，可直接用 Excel 打开
- `提交包说明.txt`：项目、Word 版本、用途和版本说明
- `package-manifest.json`：包内每个内容文件的大小和 SHA-256

提交包使用 `P001` 起始的递增版本号，不覆盖历史包，每个项目最多保留最近 20 个版本。

选择历史提交包后，系统会重新核对版本记录中的 SHA-256、ZIP 路径安全、清单格式、缺失或多余文件、每个文件的大小和 SHA-256、Word 来源、CSV 编码及内部预审标记。校验不通过时 ZIP 下载会被禁用，同时仍可下载校验报告定位问题。

## 当前边界

- MinerU 为可选本地能力，首次安装和模型下载时间较长，复杂扫描表格仍需人工复核
- 不包含多用户、角色权限和在线协同编辑
- 模板适配基于明确占位符，不承诺对任意无占位符模板进行像素级语义映射
- 不自动盖章、签名、抓取外部数据或直接提交最终投标文件
