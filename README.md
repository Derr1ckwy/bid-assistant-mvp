# 投标初稿助手

面向单人开发和小范围试用的投标文件初稿生成系统。系统把招标文件解析、要求提取、人工确认、企业资料检索、章节草稿生成、自动复核和 Word 导出串成一条可追溯流程。

当前目标不是“无人审核一键出标”，而是优先减少人工整理时间、暴露遗漏与废标风险，并确保没有企业事实依据时不编造内容。

## 已实现

- 本地创建、复制、归档、恢复和筛选投标项目
- 项目八阶段进度总览
- 项目完整 ZIP 备份、校验导入和重复项目兼容
- PDF、DOCX、TXT、Markdown 解析
- 规则模式提取项目、强制要求、评分项、资格、材料、时间和风险
- 可选 OpenAI 兼容 LLM 分析与章节生成，长文档自动分段合并
- 分析结果、原文页码、引用和章节计划的人工编辑确认
- 企业资料、产品资料、历史方案三类知识资料管理与轻量检索
- 规则或 LLM 章节草稿生成，无事实依据时保留“待补充/待确认”
- 草稿保存自动建立版本快照，可预览章节并恢复历史版本
- 自动检查遗漏、未确认条款、废标风险、缺失章节、占位符和证据缺失
- 检查工期、质保期、金额、日期、人员数量和资质有效期的跨章节冲突
- Word 导出前显示项目、章节、高风险、占位符和证据追溯检查清单
- Word 使用 V001、V002 递增版本，保留生成时间、风险摘要、版本说明和 SHA-256
- 从招标分析同步最终提交材料清单，支持人工增删、分类、状态、页码、附件关联和备注
- 资格、商务、技术、报价、签章装订及其他附件分类管理，同名文件不会静默覆盖
- 最终提交材料清单可导出为 UTF-8 CSV，必交项完成情况纳入项目总进度
- 提交包生成前检查 Word 版本、清单保存状态、必交项、附件断链和复核风险
- 使用 `P001`、`P002` 递增生成版本化 ZIP，保留最近 20 版及 SHA-256
- 提交包汇总 Word、分类附件、材料清单、提交说明和逐文件校验清单
- 专业排版 Word 初稿：A4、封面、目录、首页不同、页眉页脚、页码、分析附录和复核报告
- GitHub Actions 自动编译和测试

## 快速启动

在 PowerShell 中执行：

```powershell
Set-Location -LiteralPath 'D:\灵坤\投标系统'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\run.ps1
```

浏览器访问 `http://127.0.0.1:8501`。

不配置模型也可以使用规则模式。需要 LLM 时，在 `.env` 中填写 OpenAI 兼容接口；默认示例指向本机 Ollama。

## 项目备份

在左侧“项目管理”中可下载当前项目的完整 ZIP 备份，也可以在另一台安装了本系统的电脑上导入。备份包含源文件、分析结果、知识资料、草稿版本、复核状态、Word 输出、提交附件、材料清单和历史提交包，不包含模型密钥及其他项目。

导入时会检查备份格式、文件路径、文件数量、解压体积和 SHA-256；同一项目重复导入时会自动生成新的项目 ID，不覆盖原项目。

## Word 输出

- 正文使用宋体 10.5 磅、1.5 倍行距和统一段前段后间距，标题使用微软雅黑并设置明确字号、颜色和字距
- 封面自动调整长项目名称字号，项目信息使用固定列宽，封面不显示运行页眉和页脚
- 正文页眉左右对齐，页脚左侧保留 AI 使用提示、右侧显示页码
- 列表使用 Word 原生编号，表格使用固定宽度、单元格边距、垂直居中、隔行底色和重复表头
- 自动复核报告使用四列表格，风险行突出显示，禁止单行跨页拆分
- 存在未处理风险时必须显式确认“仅用于内部复核”，每次生成新文件而不覆盖旧版本
- Word 版本记录支持查看章节数、待处理数、高风险数和版本说明，并下载任意历史版本

当前示例成品位于 `D:\灵坤\投标系统\data\demo\示例投标文件初稿V3.docx`。固定版式用于形成可审阅初稿；获得真实甲方模板后，再增加针对性的模板映射。

## 提交包

“7. 提交清单”页可选择任意历史 Word 版本并执行提交包预检。未保存的清单修改、待准备的必交项、附件断链或缺少 Word/清单会直接阻止打包；复核问题属于警告，必须显式确认本包仅用于内部预审。

每个 ZIP 包含：

- `投标文件/`：所选 Word 版本
- `提交附件/`：按资格、商务、技术、报价、签章装订和其他附件分类
- `最终提交材料清单.csv`：带 UTF-8 BOM，可直接用 Excel 打开
- `提交包说明.txt`：项目、Word 版本、用途和版本说明
- `package-manifest.json`：包内每个内容文件的大小和 SHA-256

提交包使用 `P001` 起始的递增版本号，不覆盖历史包，每个项目最多保留最近 20 个版本。

## 当前边界

- 扫描件只提示 OCR 风险，尚未接入 MinerU
- 不包含多用户、角色权限和在线协同编辑
- 不支持任意甲方 Word 模板的像素级还原
- 不自动盖章、签名、抓取外部数据或直接提交最终投标文件
